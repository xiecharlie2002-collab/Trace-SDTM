# TraceSDTM 0.4 架构与职责边界

```text
公开或模拟来源数据
        ↓
来源登记、字段画像、格式与单位候选
        ↓
按域拆成带依赖关系的原子临床动作
        ↓
第一阶段模型：识别输出种类和目标变量
        ↓
第二阶段模型：从筛选后的注册函数中选择函数与来源编号
        ↓
政策、注册表和资源目录注入已经确定的参数
        ↓
第三阶段模型：只补全仍未知且具有有限合法选项的参数
        ↓
确定性组装并逐任务隔离失败
        ↓
人工审核候选方案
        ↓
批准的 schema_version 0.4 YAML
        ↓
受控 R 调度表 + 选择性 sdtm.oak 算法 + 版本化单位表
        ↓
DM、AE、VS 的 CSV、XPT、追溯和运行清单
        ↓
本地规则检查 + Pinnacle 21 Community
        ↓
评价明细与离线 HTML 报告
```

模型没有代码执行权限，也不能发明来源字段、连接键、单位公式、正则表达式或自由条件。来源字段使用稳定的 `ref_id`，模型不能自行拼写数据集前缀。模型分值只用于安排审核顺序。

人工审核不是形式上的确认。`accept` 接受完整候选；`modify` 必须提供能够通过注册表检查的完整步骤；必需任务不能直接拒绝；信息不足未解决时不能批准。

正式构建不读取自然语言理由，也不调用模型。转换函数和参数解析器都只能从 R 中的受控绑定表解析。注册表1.2.0同时服务于提示词、模型结果验证、审核表、YAML检查、函数调度、自动测试和函数目录生成。

三级基准共124个原子任务：基础18项、中等49项、高级57项。评价分别报告语义正确、各阶段结构正确和完整计划正确，并同时给出真实串联评价与给定正确上游结果的条件评价。通过 `assembly_group_id` 可聚合回18、20和21个旧版临床概念。

当前边界是 DM、AE、VS。Define-XML、aCRF、试验设计域、ADaM、TLF、多用户权限、电子签名、CDISC CORE 和法规申报级系统验证不在0.4范围内。
