# TraceSDTM 真实模型独立盲评

## 结论

本次实验使用 `deepseek-v4-flash` 对高级场景进行一次独立盲评。21 个临床概念中，8 个得到通过注册表严格校验的首选方案，2 个完整方案与预先冻结的专家金标准一致。

这次结果不能支持“模型已经能够独立完成 SDTM 映射”的结论。它支持的结论是：模型可以提出部分有价值的候选，但结构约束、专家审核和确定性执行仍然不可缺少。

## 盲评设计

- 实验编号：`deepseek-v4-flash-v02-blind-nonthinking-20260902`
- 场景：高级场景，只包含 DM、AE、VS
- 评价单位：21 个临床概念，其中 DM 5 个、AE 8 个、VS 8 个
- 模型：`deepseek-v4-flash`
- 温度：0
- 最大输出标记数：16,384
- 思考模式：关闭
- 提示词设计：按依赖关系分组的两阶段推荐
- 第一阶段：判断转换类别
- 第二阶段：只在第一阶段类别内选择登记函数及参数
- 盲法：提示词不包含专家金标准；模型响应冻结并计算校验值后，才调用金标准复核器
- 抽样规则：每个实际调用只采用第一次成功返回的响应，不按结果优劣挑选性重试
- 校验规则：未知类别、阶段顺序错误、未知参数、非法来源、非法目标或函数链不完整均拒绝

DeepSeek 官方接口说明 `thinking.type` 可以设为 `disabled`，用于选择非思考模式。本实验采用该参数，是因为先导调用在默认思考模式下耗尽了 16,384 个输出标记，却没有返回最终 JSON。关闭思考模式没有改变提示词、题目或金标准。[DeepSeek 思考模式说明](https://api-docs.deepseek.com/guides/thinking_mode/)

## AE 错误分析

通过结构校验不等于专业方案正确。AE 的 8 个首选方案均覆盖了所需目标变量，但只有 `AE_SAFETY` 和 `AE_REL_OUTCOME` 可以直接接受。

| 临床概念 | 评价 | 主要差异 |
|---|---|---|
| AE_SOURCE_INTEGRATION | 需修改 | 函数和连接关系正确，但 `select` 参数扩大到大量左表字段；金标准只引入右表的 `AESHOSP` |
| AE_CORE | 需修改 | 将 `PATNUM` 直接赋给 `USUBJID`，遗漏研究编号与受试者编号的组合派生 |
| AE_TERMS | 需修改 | `AEBODSYS` 直接赋值，遗漏大写规范化 |
| AE_SAFETY | 接受 | 函数、来源、目标和参数均一致 |
| AE_REL_OUTCOME | 接受 | 函数、来源、目标和参数均一致 |
| AE_START | 需修改 | 使用完整日期时间函数并假设 `m/d/y`，未识别 `dd-mmm-yyyy` 和不完整日期 |
| AE_END | 需修改 | 除日期函数和格式错误外，持续事件标志遗漏结束日期来源字段 |
| AE_SEQUENCE | 需修改 | 序号排序字段遗漏 `AEDECOD` 和来源行号，重复记录时稳定性不足 |

## 结构错误分析

DM 的原始响应是合法 JSON，但 `categories` 使用了 `[1, 2]` 之类的数字，而不是注册表中的 `direct_assignment` 等类别名称。这说明“只能使用给定枚举”的自然语言约束仍可能被模型忽略。

VS 使用了合法类别名称，但把 `record_transposition` 放在字段映射和日期转换之前，违反项目登记的执行阶段顺序。模型理解了所需转换类型，却没有稳定地遵循可执行顺序。

当前系统按依赖连通组进行原子校验，因此一个分类错误会使整组无法进入第二阶段。这符合正式构建的保守原则，但会放大单个模型格式错误对推荐覆盖率的影响。后续可以同时保留组级上下文和概念级隔离：错误概念停止，其他概念继续生成候选，并在最终批准时继续要求整个依赖闭包完整。

## 对项目优化的启示

1. 第一阶段应优先采用接口级严格结构模式或函数调用参数模式，把类别限定为真实枚举，而不只依赖自然语言要求。
2. 在提示词和参数模式中显式提供类别阶段序号，并要求模型输出阶段序号；系统仍独立复核顺序。
3. 对第一阶段采用逐概念隔离校验，同时保留同组上下文，减少单个格式错误导致整组候选缺失。
4. 日期格式候选和不完整日期证据应在概念附近重复展示，减少模型忽略组级字段画像的概率。
5. 对 `USUBJID`、序号变量和不完整日期等高风险派生增加专门反例，强调“目标变量集合正确”并不代表函数链正确。
6. 评价必须同时报告总体分母和通过结构校验后的条件分母，不能只报告 2/8 或 8/8。
